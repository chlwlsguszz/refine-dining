# 육류·가금류 실측 조리 수율

미국 농무부 농업연구청(USDA ARS)이 2014년 9월 발표한 *USDA Table of Cooking Yields for Meat and Poultry, Release 2*의 [공식 원본 통합문서](https://www.ars.usda.gov/ARSUserFiles/80400535/Data/retn/USDA_CookingYields_MeatPoultry02.xlsx)를 [이 디렉터리](USDA_CookingYields_MeatPoultry02.xlsx)에 보관했다. 측정 조건과 열 정의는 [USDA 연구 방법서](https://www.ars.usda.gov/ARSUserFiles/80400535/Data/retn/USDA_CookingYields_MeatPoultry02.pdf) 5, 6, 13–18, 24–25, 27–28쪽에서 확인할 수 있다. 1975년 항목의 기초 자료는 [Agriculture Handbook 102](https://www.ars.usda.gov/ARSUserFiles/80400530/pdf/ah102.pdf)다.

## 수율 조회와 계산

중량 계산기는 식품명을 자유롭게 검색하고 비슷한 실험 기록을 찾는 흐름을 제공한다. 검색 범위는 원표의 **173개 조건별 기록 전체**다. 사용자가 찾은 기록의 부위·지방 구간·손질 상태를 확인하면 `조리 전 g × 평균 수율(%) ÷ 100`으로 참고 중량을 계산한다. 검색 유사도는 계산 적용 가능성이나 정확도를 뜻하지 않으며, 명시적인 조건 충돌은 서버에서 별도로 검사한다. 최저·최고 값은 해당 연구의 관측 범위다.

### 식품명으로 실험 기록 찾기

이미 식품 매칭에 사용한 로컬 E5 모델과 Python 환경이 있으면 다음 명령으로 검색기를 켤 수 있다. 저장소 루트에서 첫 명령을 실행하고, Spring을 실행할 별도 터미널에서 환경 변수를 설정한다. 외부 LLM API 호출은 없다.

```powershell
backend/build/e5-env/Scripts/python.exe backend/tools/cooking_yield/suggest_names.py
# Spring을 시작할 터미널
$env:YIELD_SEARCH_URL = 'http://127.0.0.1:18086'
```

검색기는 `POST /search`에서 `foodName`, `cookingMethod`를 받아 원표 ID와 코사인 유사도를 반환한다. 영문 원명·한국어 검색어·부위·조리법을 E5로 벡터화한다. 축종을 명시하면 해당 축종 안에서 검색하며, 부위와 조리법이 명시적으로 맞는 기록을 앞쪽에 배치한다. 검색 순서는 코사인 점수에 부위 일치 0.04, 조리법 일치 0.02를 더하고, 요청하지 않은 용액 첨가 처리에는 0.015를 빼 정한다. 응답의 `score`에는 가산 전 코사인 점수를 그대로 담는다. 점수는 확률이 아니다.

최대 12개 기록을 반환하며 일반 검색 최소 코사인 값은 0.78이다. 축종·부위가 모두 불분명한 표현은 0.86 이상이어야 한다. 감자·옥수수·두부처럼 이 육류·가금류 원표에 없는 것으로 확인되는 식품은 결과를 비운다. 이 기준은 검색 후보를 만드는 정책이며 통계적으로 보정한 적용 판정 기준이 아니다. 최근 128개 질의는 메모리에 캐시한다.

‘소고기 안심’은 기존 28행에 없던 안심 실험을, ‘닭다리살’은 넓적다리와 아랫다리 실험을 찾는다. ‘껍질 없는 닭 넓적다리’에도 껍질 포함 기록을 검색 결과로 보여줄 수 있지만, 이것이 같은 조건이라는 뜻은 아니다. 서버가 차이를 표시하고 적용을 제한한다. 기존 `/suggest`의 제한적인 대체 식품명 추천도 호환용으로 유지한다.

## 수록한 원표 행

원본 Sheet1의 음식·조리 조건 **173행 전체**를 수록했다. 163행은 NDB 코드가 있고, 코드가 없는 합산 기록 10행은 고정된 원표 행 번호로 식별한다. 소고기, 돼지고기, 닭, 칠면조, 송아지, 양, 에뮤·타조·들소·사슴·엘크가 포함된다. 채소·곡류·수산물은 이 출처에 없다.

먼저 상세히 정리했던 28행의 ID·수치·한국어 조건·식품코드 연결은 유지했다.

- **닭 9행.** 껍질을 포함한 가슴·아랫다리·넓적다리·날개와 해당 부위에 측정된 오븐구이, 약불 삶기, 브레이징을 포함한다. 자료에서 뼈 포함 여부를 명시하지 않은 행은 화면에도 미기재로 표시한다. 2011년 닭 브레이징 연구는 뼈를 발라내기 전에 계량했다. 껍질을 제거한 국내 닭가슴살 코드는 연결하지 않았다.
- **소고기 9행.** 소고기 패티의 무유 팬구이·브로일/그릴과 다짐육 부스러기의 팬 볶음을 각각 지방 12% 미만, 12–22%, 22% 초과로 구분한다. 패티의 브로일/그릴 행은 연구에서 오븐 브로일로 조리했음을 함께 보여준다.
- **돼지고기 10행.** 다진 돼지고기의 패티·부스러기 각각 지방 10% 미만, 10–27%, 27% 초과를 구분한다. 패티의 표에는 ‘Broiled or Grilled’라고 기재돼 있고 방법서의 실험 기구는 전기 팬이다. 돼지 등심은 뼈가 있는 센터 로인 찹과 뼈를 제거한 톱 로인 찹 각각 두 조리법을 수록했다.

국내 원본의 닭고기 넓적다리·아랫다리·날개와 돼지고기 등심 코드는 해당 부위의 후보를 찾는 데 쓴다. 미국식 절단 부위, 껍질·뼈 상태, 지방 함량, 조리 방법은 원문을 보면서 확인해야 한다. 반죽, 소스, 기름, 육수 등을 더해 얻은 완성 요리 전체의 중량은 포함하지 않는다.

추가한 145행은 원문 식품명·조리법을 그대로 보존하고, 검색을 위한 한국어 부위 표현을 덧붙였다. 한국어 검색어는 국내 절단 부위와 미국식 절단 부위가 완전히 같다는 선언이 아니다. 알 수 없는 온도·시간·중량 기준을 새로 만들어 넣지 않았다. `species`, `cut`, `methodKey`, `preparationTags`는 원문에 드러난 조건을 정리한 검색·검사용 메타데이터다. 서로 다른 여러 부위를 합친 기록은 `aggregate`로 표시한다.

## 수치 해석

수율은 원래 시료 중량 대비 조리 후 시료 중량의 백분율이다. 조리 전 중량(g)에 평균 수율을 곱해 100으로 나누면 해당 조건의 예상 조리 후 중량(g)이 된다. 표에 최소·최대가 있을 때 같은 식으로 환산한 두 값은 **연구에서 관측한 범위**다. 한 사람이 다음에 조리할 때의 예측 구간이나 신뢰구간은 제공하지 않는다.

표가 보고한 `n`, 최솟값, 최댓값은 각각 유지했다. 표의 빈칸과 `n/a`는 JSON `null`로 둔다. 기존 28행 중 1975년 닭 자료 6행은 표본 수 미기재, 2011·2013년 닭 자료 3행은 표본 1건에 범위 미기재다. 각 레코드에 USDA NDB 식별자(있는 경우), 시트 셀 범위, 영어 식품명·조리법, 해당 행의 자료 연도가 있다.

송아지 간의 팬 조리 기록(NDB 17204)은 원표 평균 68%, 관측 최고 67.64%로 평균이 정수 반올림되어 범위 밖에 있다. 수치를 임의로 바꾸지 않고 `statisticNote`를 남겼다. 변환기는 이처럼 0.5%p 이내의 평균 반올림만 허용하며, 범위 순서와 표본 수는 별도로 검증한다.

예를 들어 NDB 05094, Sheet1 74행의 껍질 포함 닭 넓적다리 오븐구이는 평균 69%, 관측 58–79%이므로 200g 입력은 예상 138g, 관측 범위 환산 116–158g이다. 뼈의 중량을 빼거나 한국산 품종에 맞게 조정한 결과는 아니다. 지방 12% 미만 소고기 패티의 팬구이는 NDB 23564, Sheet1 24행에서 평균 77%, 관측 76.37–78.30%, 표본 4건을 확인할 수 있다.

## 재현

원본 통합문서 SHA-256은 `13bd2cec633841867bf8532ed57114c81f3791b9bcd35a396dec6a1b960773ff`이다. 프로젝트 루트에서 Python 3.10 이상으로 실행한다. 표준 라이브러리만 사용하며 다운로드나 모델 호출이 필요하지 않다.

```shell
python backend/tools/cooking_yield/import_usda.py
python backend/tools/cooking_yield/import_usda.py --check
```

[변환 코드](../../backend/tools/cooking_yield/import_usda.py)는 원본 해시·열·매핑·표본 수·관측 범위를 검증하고 [서버용 JSON](../../backend/src/main/resources/cooking-yields.json)을 만든다. `--check`는 재계산한 결과와 패키징한 파일이 일치하는지 확인한다. 홀드아웃 평가에서 쓰는 외부 연구 관측값은 이 변환의 입력에 포함되지 않는다.

이전에 보관한 [외부 패티 평가](evaluation/README.md)는 당시 28행의 조건 선택 API를 대상으로 한 기록이다. 전체 173행의 검색 정확도를 검증한 결과로 해석하지 않는다.
